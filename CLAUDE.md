# Portcullis Keycloak — Claude Code Instructions

## Project Overview

The Portcullis sign-in extension for Keycloak 26.8.1, published as `ghcr.io/porelli/portcullis-keycloak` (the official Keycloak image pinned `tag@sha256` plus `portcullis-signin.jar` in `/opt/keycloak/providers/`). It reads the Hub's `signin-keycloak.json` (core mounts `hub_data:/hub-data:ro`) and enforces sign-in methods and templates inside Keycloak. The cross-repo interfaces are defined in `portcullis-docs/docs/guides/integration-contracts.md` (§1, §8, §8.1) — change that page first.

## Merge order (cross-repo features)

The contract's order is docs → keycloak (wait for `edge`) → Hub → core. Keycloak goes before the Hub and core, so on keycloak `main` the `vectors` job compares with Hub/core `main`, which don't have the feature's vectors / realm yet, and that run publishes nothing. One time per feature, after the merge to keycloak main, run `gh workflow run build.yml -R porelli/portcullis-keycloak --ref main -f compare_ref=<feature branch>` while that branch still exists on the Hub and core. That run compares against the feature branch and publishes `edge`. Push runs on main always compare against main, and they go green again once the Hub and core have merged.

## Critical Rules

- **Contract first.** `integration-contracts.md` §8.1 is the source of truth for `signin-keycloak.json`, the methods, rules, `pc_method`, `pc_fresh` and the provider ids; change it before the code. The rule evaluation must give the Hub's results (`internal/signin`): the shared vectors are the check.
- **Fail closed.** A missing, unreadable or invalid `signin-keycloak.json` is `DENY_ALL`: nobody signs in. An unknown method, rule shape or file version denies; a method that is off is never accepted.
- **Secrets** never on argv or in logs (the CI smoke run's admin password comes from the environment and a 0600 file).
- **Supply chain.** Every image `tag@sha256`; every action pinned by full commit SHA with a `# vX.Y.Z` comment; Gradle wrapper with `distributionSha256Sum`; `verification-metadata.xml` with sha256 for every artifact. Keycloak's own SPI and the libraries it ships (webauthn4j, Jackson, jboss-logging, jakarta.persistence, jakarta.ws.rs) are `compileOnly` (the tests see them too: `testImplementation` extends `compileOnly`), non-transitive, at exactly the versions Keycloak 26.8.1 ships (keycloak-parent / quarkus-bom); a Keycloak bump moves the base image and these together, by hand (CI fails when the Dockerfile's Keycloak tag and `val keycloak` differ; Dependabot ignores these artifacts, the JUnit BOM and Keycloak minor/major image updates). Dependabot (gradle, docker, github-actions) doesn't regenerate `verification-metadata.xml`: a Gradle bump needs it regenerated and pushed to the PR.
- **Prefer mature libraries**: Keycloak's SPI, webauthn4j (attestation parsing, cert-path validation), Jackson, the JDK's `CertificateFactory`; no hand-rolled X.509 or CBOR code.
- **No migration code**: there are no installs to upgrade from (the Liquibase changelog has one changeset; edit it rather than adding one until there is an install).
- **Test-only libraries** (Hibernate, Liquibase, H2, BouncyCastle) are at the versions Keycloak 26.8.1 runs (quarkus-bom) or webauthn4j-test brings; they never reach the jar.
